4. What we calculate (not Kissflow)

After rows are in memory:

  1. Entity = Refex (Venwind off this tab)
  2. Me = live pending or Closed By you or live reopen in your bucket. My Team = !Me
  3. Period = Weekly / Monthly / FY (Today’s Snapshot skips period)
  4. Count:
KPIRule
All TicketsRows in Me or Team
Pending ApprovalLive at IT Head Approval (Me). Team = L1+L2+Manager+Head except your Me tasks
Open TicketsLive bucket + agent pipeline open (not approval, not reopen-hold)
SLA BreachedOpen SLA ⊂ Open; Closed SLA ⊂ Closed. Pending Approval is not SLA Open
RejectedRejected + you closed/modified (Me) / any rejected (Team)
ClosedReOpen window or process Completed — not Statu_1

Source chips use the same rows (no extra API).

7. Why it feels slow (Head Refex)

Aligned with the existing Kissflow performance ticket; Head-specific facts:

CauseEvidence
No aggregate KPI APIWe must download pending queues + the full ~790-row report to count Closed/Team/SLA
Kissflow shell, not our React paintParent loaded 250 assets; many chunks ~7.8 s; Head cards stayed 0 for tens of seconds
Pending is 1 + N callsCount, then one list per live StepName. User Me had at least Head Approval (29) + Reopen (17)
Report payload is hugeTwo pages, ~3.1 MB, ~790 tickets — ~0.8 s network, then heavy client map/merge
Intentional 2.5 s waitHead Me delays Phase B so first paint is not blocked; Closed/Team from the full report arrive later
Report vs pending lagPending is live; report can lag. We merge by instance id in the pack
$created_at_gt not trustedPeriod (FY) is applied in the browser after download

The UI render of the KPI cards is not the bottleneck. Kissflow shell + multiple pending calls + full report download + client rules are.

8. What we already do (client)

Same as the performance ticket: landing seed, skip $request_id on land, IndexedDB cache, soft delta, no KPI flash to zero, no participated walk on Head Me land.

9. What we need from Kissflow (Head)

  1. Aggregate KPI API (All / Pending Approval / Open / Closed / SLA by user + period)
  2. Reliable server-side $created_at_gt / $modified_at_gt / entity / company
  3. Closed-by-user query (not full report)
  4. Documented StepName → ActivityId + pending rate limits
  5. Guidance on page_size for a ~3 MB / 790-row Service_Items_Refex_A00 report
